## 04.11.2026 · `feature/stage5-history` · рабочий ПК — новая оценка, этап A: юридическое совпадение

План оценки по схеме Ivan — `.claude/plans/jolly-sparking-yeti.md` (этапы A–E): уровень 1 «юридическое
совпадение» → синий «Alternativa»; оцениваются все участники; история и карточки товара; окно tkinter.

**Решено (Ivan)**
- Декларативно = юридическое совпадение запроса и предложения: всё из запроса названо в Anexa 22 и выполнено.
  Кабель «для Dräger 120» без указания совместимости, электрод 50x50 вместо 30x30 — не совпадает → синий.
- Оцениваются все участники (человек останавливался на первом зелёном, система — нет).
- Окно — своё приложение tkinter с логом и этапом, всплывает, когда нужен выбор.

**Сделано (этап A)** — `src/anexa22/requirements.py`
- Число засчитывается только при родственной подписи (основа слова — 6 букв: «Manșete»/«Manseta»);
  «diametru ≥ 5 cm» больше не закрывается «lungime 150 cm». Условие без подписи — любым подходящим значением.
- Размер AxB — целиком («30x30 mm (A22: 50x50 mm)»); «18 G» — калибр, не граммы.
- Совместимость: «compatibil cu / pentru …» в запросе и коды аппарата из названия лота (B1) должны быть
  в предложении (спецификация + модель + позиция A22) — иначе «compatibilitate neindicată».
- Признаки: steril, unică folosință / reutilizabil, adult / pediatric / nou-născut, fără latex.
- `DeclarativeCheck.status` = ok / alternativa; `OfferCheck.declarative`; `check_offer(..., title, offered_extra)`
  из `fill_offers` и `clarificari`. Цвета пока прежние — синий появится в этапе E.

**Цифры (21643233)** — уровень 1 по 253 офертам: ok 233, alternativa 20. Причины: значение/признак не совпал 13,
нет признака 9, нет числа 7, нет совместимости 4, другой размер 2. Примеры: Labromed, лоты 366–374 (LLETZ:
высота 10 вместо 7 мм, длина 11 вместо 12 см); лот 277 — кабель 2.4 m вместо 1,21 m; Dutchmed, лот 280 —
не указано adult/pediatric.

**Открыто** — этапы B–E.

### Этап B — база решений и движок оценки

**Сделано**
- `src/history/db.py`: таблицы `products` (карточка товара), `lot_profiles` (запрос лота), `evaluations`
  (решение по оферте: corespunde / alternativa / nu_corespunde / clarificare / neevaluat; source auto / human /
  pending), `questions` (очередь для окна: offer_status / product_card).
- `src/evaluate`: `engine` читает result + манифест, оценивает **всех** участников лота по цене: ≥ 130% —
  nu_corespunde; уровень 1 не совпал — alternativa (дальше не проверяем); иначе уровень 2 (документы),
  AMDM (локальная копия реестра), история (`history.lookup`: карточка и прошлые решения по `model_key`).
  `confidence.decide`: авто-«corespunde» только если документы подтвердили, AMDM verde, карточка подтверждена
  и модель раньше принималась человеком; иначе вопрос с предложением системы. Решение человека не
  перезаписывается, вопросы не дублируются.
- CLI: `python -m src.evaluate <result.xlsx> downloads/<тендер> [--dry-run] [--online]`. Тесты — `tests/test_evaluate.py`.
- Уровень 1: число после марки («Drager 120») — модель, «de 54 grade» — нет (лот 483).

**Обнаружено**
- `resources/amdm_registry.sqlite` на этом ПК пропал (создан пустым 04.11) — восстанавливается `python -m src.amdm
  check … ` (сайт, ~10 мин).

**Цифры (21643233, --dry-run, пустая база знаний, без AMDM)** — 253 оферты: alternativa 12 (авто),
nu_corespunde 38 (цена ≥ 130%, авто), вопросов 203 (+154 карточки товара). Ожидаемо: на пустой базе нет
подтверждённых карточек и истории — всё, что не отсечено законом и уровнем 1, спрашивается.
