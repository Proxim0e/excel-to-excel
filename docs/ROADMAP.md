## Классификация (этап 1)

Классифицируется каждый уникальный по содержимому документ, один раз; копии в лотах получают тип через манифест. Текст всех страниц хранится в `document_pages` — пригодится этапам 2–4.

- 23 типа: Anexa 22, Anexa 23, DUAE, cerere de participare, декларации, гарантии, справки SFS, выписки, банковские счета, учредители, финотчёты, ISO, CE/DoC, регистрация AMDM, авторизация производителя, доверенность, Agenția de Mediu (EEE), даташиты и др. Полный список — лист «Типы» в таблице проверки.
- Тип определяется по «шапке» первой страницы (уверенность 0.9), затем по тексту первых двух страниц (0.6), затем по имени файла (0.4 / 0.3 для сканов). В тексте Anexa 22/23 узнаются только по заголовкам колонок: общие слова «specificații tehnice» встречаются в декларациях.
- **Классификация по страницам.** Встречаются PDF-«пачки» со всей офертой в одном файле (у 3 из 24 участников Anexa 22/23 лежат внутри таких пачек). У каждой страницы свой тип, продолжение таблицы Anexa наследует тип предыдущей страницы; у документа — список разделов `contains`.
- **Сканы.** 80 из 475 уникальных документов (17%) — картинки, текст у них только в штампе подписи MoldSign. В основном регистрационные удостоверения («lotul N reg»), справки банков, сертификаты. Тип для них — по имени файла с низкой уверенностью; для их содержимого понадобится OCR (решать на этапе 4). Anexa 22/23 среди сканов нет.
- Результат на 21641880: у всех 24 участников найдены страницы и Anexa 22, и Anexa 23; без типа («other») 14 документов, без текста и подсказки в имени («no_text») 24.
- **Точность против разметки Ivan** (471 документ, `downloads/21641880/classification_gold.xlsx`, разметка по группам «Documente generale / Document tehnic / ISO/CE/DM / anexa22 / anexa23 / anexa22/anexa23»): **95.1%** по группам; с текстовым слоем — 98.2% (384/391), сканы — 64/80 (по имени файла). Anexa 22, Anexa 23 и пачки с обеими анексами — 100%. Пересчёт: `python -m src.classify downloads/21641880 --evaluate`.
- Оставшиеся ошибки: 16 сканов без подсказки в имени (нужен OCR), 3 документа с битым или пустым текстовым слоем, 2 пачки «documente generale», 2 спорных CE внутри технических документов.
- **Спросить один раз (классификация):** `classification_review.xlsx` в папке тендера, колонка «Правильный тип» (выпадающий список). Исправления применяются в начале следующего запуска (или `python -m src.classify <папка> --apply`), сохраняются как `type_source = human` и правилами больше не перезаписываются.
- Без текстового слоя — 2 из 448 проверенных уникальных файлов.
- По имени файла Anexa 22/23 узнаётся примерно в трети случаев — классифицировать нужно по тексту.
- Полный прогон: сканирование 283 лотов ~1 мин (8 потоков), скачивание 718 файлов ~21 мин.

## Разбор Anexa 22 (этап 2)

Где реально уходит время у Ivan: перенос модели, предложенной спецификации, DM/ISO из Anexa 22 в Excel. Тендеров в год ~10–12 больших и ~30 меньших, участники одни и те же (~50–60 компаний) — поэтому память по участнику окупается быстро.

- Все Anexa 22 тендера 21641880 — таблицы с линиями, их находит PyMuPDF (`find_tables`), включая повёрнутые страницы. Раскладка у каждого участника своя: шапка формы внутри таблицы, заголовки в несколько строк и вертикальными буквами, объединённые ячейки, «Ţara de origine Producătorul» одной колонкой, номер лота строкой-разделителем во всю ширину.
- Колонки сопоставляются по x-координатам заголовка, а не по номеру колонки; продолжение таблицы на следующих страницах определяется по положению таблицы, а не по типу страницы (продолжения часто классифицированы как amdm/datasheet из-за номеров DM в шапке).
- Результат — таблица `anexa22_offers` манифеста: участник, лот, CPV, позиция, модель, страна, производитель, требуемая и предложенная спецификация, стандарты, номера DM. На 21641880: 597 строк, 252 лота, 24 участника, DM у 395 строк.
- **Точность против Excel Ivan** (`21641880 CDM27 B — копия.xlsx`, 305 заполненных оферт): найдено 100% оферт; производитель 99.3%, страна 99.0%, спецификация 96.6% (доля слов эталона), DM 93.9%, модель 84.1%. Пересчёт: `python -m src.anexa22 downloads/21641880 --gold "<Excel>"`, расхождения — `anexa22_vs_excel.xlsx` в папке тендера.
- Значительная часть расхождений — в эталоне, а не в разборе: у Ecochimie префикс модели в Excel («26288/…») отличается от PDF («26263/…») при совпадающем коде; у DITA модели соседних лотов скопированы (лот 20 — «10mm» вместо «15mm»); номера DM, которых нет в Anexa 22 (взяты из других документов или опечатки). DM нет в Anexa 22 у ICS Eyecon и Denolga — их нужно искать в документах AMDM (этап 4).
