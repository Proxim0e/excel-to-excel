# ADR-001: Манифест документов пишется при скачивании, а не восстанавливается по папкам

**Статус:** принято
**Дата:** 28.10.2026
**Решает:** Ivan

## Контекст

Этапу 1 ([ROADMAP](../ROADMAP.md)) нужна таблица «файл → тип → участник → лот». Источник истины об участнике, лоте, исходном имени файла и ссылке — скрапер. Папки на диске — лишь производное от него, к тому же с потерями: `sanitize_filename` обрезает имена до 40 символов и убирает символы. По концепту база — SQLite, ядро отдельно от интерфейса, без жёстких путей.

## Варианты

### A: восстанавливать по структуре папок

| Критерий | Оценка |
|---|---|
| Сложность | низкая |
| Надёжность | низкая: обрезанные имена, совпадения имён, нет ссылок |
| Повторное использование | плохое: каждый этап снова разбирает пути |

### B: при скачивании писать строки в SQLite (`downloads/<tender>/manifest.sqlite`)

| Критерий | Оценка |
|---|---|
| Сложность | средняя: модуль манифеста + запись из `download_worker` |
| Надёжность | высокая: точные данные скрапера |
| Повторное использование | хорошее: этапы 2–4 и импорт архива читают одну базу |

## Решение

Вариант B. Таблицы:

- `documents` — один уникальный файл (`sha256`, размер; позже тип, уверенность и источник типа: правило / LLM / человек, число страниц, наличие текста);
- `document_refs` — каждое место, где файл лежит в тендере (`tender_id`, номер и название лота, участник, исходное имя, ссылка, путь, `sha256`, статус скачивания).

Тип определяется один раз на хеш, `document_refs` связывает хеш со всеми лотами. Строка пишется для любого исхода задачи: скачан, скопирован, уже был на диске. Поэтому для уже скачанного тендера отдельный перенос не нужен: повторный запуск скрипта пропускает файлы и заполняет манифест.

## Последствия

- Проще: дедупликация — запрос к базе; этап 2 получает список уникальных Anexa 22/23 вместе с участниками; этап 4 берёт номера DM из той же базы.
- Сложнее: главный скрипт пишет в SQLite из нескольких потоков (запись под блокировкой).
- Вернуться позже: привести схему к модели данных концепта (оферты, модели) на этапе импорта архива.
