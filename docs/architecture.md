# Архитектура (слои)

Цель: разделить ответственность, чтобы код был читаемым и расширяемым.

Слои:
- Domain: модели данных (Lot, Participant, Tender), бизнес-правила (формирование заголовка B1, нормализация строк).
- Application: оркестрация процесса (pipeline): прочитать родительский Excel → создать/обновить листы → записать поля → (опционально) скрап → сохранить.
- Infrastructure: адаптеры для openpyxl (Excel) и requests+BS4 (scraping), логирование, загрузка конфигов.
- Interfaces: CLI команды (process, scrape, validate-config).

Поток данных (в общих чертах):
1) Найти родительский файл (по префиксу/паттерну) → загрузить книги.
2) Определить существующие листы "lot N" в шаблоне.
3) Пройти по строкам родительского файла: создать/обновить листы и записать поля.
4) Скрапинг: собрать участников и записать их в соответствующие листы.
5) Сохранить итоговый файл с таймстампом.
